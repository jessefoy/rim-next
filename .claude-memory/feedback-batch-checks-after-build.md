During a multi-phase build, collect everything Jesse needs to check (read-aloud wording, things to try signed in, issues noticed in passing) in one saved list and keep building. He reviews it all in one thorough session once every phase is done. For the Programs and Registration build the list is `mockups/registration-2026-10-23/BUILD_PLAN.md` → "To check once everything is built".

**Why:** Jesse, 2026-10-24, as the build grew bigger than he expected: "Let's save all the things that we need to check for after everything is built. That way, we have a nice, thorough session where we're looking at everything. For now, let's continue." Earlier the same day: "I'll come back to these to-dos after we've gone through all of the phases."

**How to apply:** at the end of each phase, add its new wording, trials and findings to the list (and note it in the wrap-up), then move on. Don't end turns asking him to read aloud or test each piece. Still ask the decisions that block the next phase, and still never write to production for a test without his yes. Read-aloud ratification is still his alone; deferring it doesn't make the wording final. Related: [[feedback-ask-flags-as-questions]], [[feedback-check-live-test-side-effects]].
