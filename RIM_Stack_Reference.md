## What's been built

Rooted In Mindfulness (RIM) is a community Insight Meditation center in Brookfield, WI. This Next.js application is the **single, integrated RIM platform** — public pages, member accounts, registrations, online courses, hubs, volunteer tools, the API, the database, business logic, scheduled jobs, and the stateful interactive surfaces (the Tiptap editor surfaces, the LiveKit session room, the staff tools) all live here, in one app.

**The April 2026 Webflow-primary pivot was reversed (May 2026).** RIM is no longer split between a Webflow front-end and a headless backend. The legacy Webflow public site (at `rootedinmindfulness.org`) is being **retired and rebuilt natively in this app**; the Webflow bridge (`rim-connect.js`, the `/api/public/*` routes) has already been removed. The public-facing pages exist in the app today but are early/rough — they are the next major build area, not duplicates of something live elsewhere. `RIM_Architecture_Directive.md` and `RIM_Architecture_Pivot.md` are kept only as superseded historical record; do not treat them as current.

## Workflow

- **Never run a local dev server.** Push to `main` → Vercel auto-deploys in ~1–2 min.
- `npm run build` = `prisma generate && node prisma/migrate.mjs && next build` — run locally to catch TypeScript errors before pushing. Note: locally the full build will fail at `migrate.mjs` unless `.env.local` is loaded, because it needs `POSTGRES_PRISMA_URL`. To type-check without DB: `npx tsc --noEmit`.
- **`prisma/migrate.mjs` skips cleanly when DB env is missing.** Top-of-`main()` guard: if `POSTGRES_PRISMA_URL` is absent, log a friendly note and return. Production deploys always set the env and run migrations. Vercel preview deploys (which don't inherit production env vars by default) complete `next build` without DB access. Established session 116 after the first non-main branch push surfaced the pre-existing fragility.
- To pull env vars: `npx vercel env pull .env.local`
- To run DB migration: `set -a && source .env.local && set +a && npx prisma db push`
- Route protection: `proxy.ts` (not `middleware.ts` — Next.js 16 naming)
- `params` is `Promise<{slug}>` in App Router — must `await params` before destructuring.
- **Mobile viewport:** `app/layout.tsx` exports `viewport: Viewport` with `width: "device-width", initialScale: 1`. Required — without it mobile browsers render every route at ~980px desktop width and silently ignore every `@media (max-width: 768px)` rule. Do not remove. (Added session 88 after the whole platform was discovered to be rendering as desktop-scaled on phones since inception.)
- **Cron rules-of-thumb:** Neon Free-tier compute = 100 CU-hrs/mo ≈ 24/7 active time of a `.25 CU` compute. A cron firing more than hourly will keep the endpoint continuously active and exhaust the cap. Use hourly (or less frequent) for DB-hitting crons; if real-time syncing is required, upgrade the plan or use a manual-sync UI pattern.

**Session room permission model — identity vs. capability (2026-05-26 split).** The session-121 / session-124 single-flag model conflated *identity* (who is the assigned steward) with *capability* (who can do which actions). The 2026-05-26 audit and refactor split them. `lib/livekitAuth.ts::resolveSessionRole(userId, programSlug, sessionDate, roles)` now returns `{ isSessionHost, hasEndAllAuthority, isCoHost, isHostTeam, isProgramTeacher }` and is used by every server route that gates a session-room action (token, step-in, mute-participant, mute-all, end-session).

**Identity** — drives the three role pills:

- **Host** (singular) = `HostAssignment` match for this exact session. **No role bypass.** Drives the "Host" pill. An ADMIN or GUIDING_TEACHER visiting a session does *not* show this pill — that label is identity, not capability.
- **Teacher** = `ProgramTeacher` row for this program. Layered on top of Host. Drives the "Teacher" pill and the bell-friendly `teacher` audio profile (NS off, AGC off, 128 kbps).
- **Host Volunteer** (renamed from "Co-host" 2026-05-26 — metadata field name `cohost` and CSS class kept stable) = Co-host capability AND not Host AND not Teacher. Drives the "Host Volunteer" pill (muted slate). Catches host-team `HubMember` records (active + hostingCapability), `HOST_MANAGER`, ADMIN, GUIDING_TEACHER.

A tile renders at most two pills (Host + Teacher); never three. `cohost` is set only when neither of the other two applies, enforced both server-side and in the client-side belt-and-suspenders `setMetadata` effect in `RIMConference.tsx`.

**Capability** — drives the buttons and the server gates:

- **`hasEndAllAuthority`** (drives End button label + `/api/livekit/end-session` gate + EndMenu's "End for all" option) = assigned Host OR ADMIN OR GUIDING_TEACHER OR (Teacher when no `HostAssignment` exists for this session). The teacher-fallback rule (new) handles the "Maria teaches alone" and peer-led-community-sit cases without forcing a Step-In first. Reactive at token-issue only — the server re-runs `resolveSessionRole` on every `/end-session` call as the authoritative gate, so a stale token-issued button at worst yields a 403 after the room state changes mid-session.
- **`isCoHost`** (drives mute-others / Mute All / Bell mode toggle / per-tile hover mute / Participants management / Share Screen) = Host OR Teacher OR Host Volunteer. ADMIN bypass. Share Screen was extended from Session-Host-only to all Co-hosts (2026-05-26) — closes a latent bug where Host Volunteers saw the share button but the token didn't grant the source. Resolution still goes through `getEffectiveHostingCapability(userId, "host-team", isManager || isProgramTeacher)` where the role-based grant is the fallback when no `HubMember` record exists; an existing record is authoritative — if it's paused or revoked, the gate denies Co-host capability even for `HOST_MANAGER` and `ProgramTeacher`.

**Token grants** at issuance (`createRoomToken(userId, name, room, permissions, metadata)`):

- Session Host or Co-host: `roomAdmin: true`. Co-host implies `canShareScreen: true` (extended 2026-05-26).
- Participant: `canPublishSources: [MICROPHONE, CAMERA]` only.

**Token metadata** carries three orthogonal flags seeded by `app/api/livekit/token/route.ts` and `app/api/livekit/step-in/route.ts`:

- `host: true` ↔ `isSessionHost` (drives Host pill)
- `teacher: true` ↔ `ProgramTeacher` (drives Teacher pill)
- `cohost: true` ↔ has Co-host capability AND not Host AND not Teacher (drives Host Volunteer pill)

Trust note: `canUpdateOwnMetadata: true` (lib/livekit.ts) lets a client rewrite their own metadata, so the pills are UI cues only — real actions are gated server-side via `resolveSessionRole` on every action route.

**Why the split.** The pill is identity; the button is capability. An ADMIN visiting a session retains End authority as a safety override, but doesn't misrepresent themselves as the assigned host. A teacher teaching alone gets End naturally via the fallback, but their tile still shows Teacher (which is what they actually are). Host volunteers helping out have full mute/share/Bell-mode capability — but they're labeled Host Volunteer, because the formal Host of this session is someone else (or no one yet, if they want to Step-In and become it). The pre-split single-flag model surfaced as the bug Jesse reported: joining as ADMIN with no assignment showed the Host pill on every session, defeating the "Session Host (singular)" design.

**`isHostTeam` (Step-In gate, session 124).** Same hub-gate call with a narrower fallback (`isManager` only — ProgramTeachers don't gate Step-In because they teach in the room, they don't run it). Subtle change worth knowing: plain `HOST` role members without an active host-team `HubMember` record no longer see the Step-In button. The session-92 `syncHubMembership` flow creates the record on role assignment, so this should be a no-op in practice; flag if any host reports the button missing. As of 2026-05-26 ADMIN-without-assignment also sees the Step-In button (since they no longer auto-grant Host identity); tapping it writes a real `HostAssignment` and creates an audit trail for who actually ran the session.

`createRoomToken(userId, userName, roomName, permissions: { roomAdmin, canShareScreen }, metadata?)` — the previous `(isHost: boolean)` signature was removed. `canPublish: true` was replaced everywhere with `canPublishSources` so the participant tier physically cannot publish a screen-share track regardless of what their UI tries to do.

Client-side, `components/session/sessionRole.tsx` provides `SessionRoleContext` with `{ isSessionHost, isCoHost, programSlug, localIdentity: string | null }` — descendants of `RIMConference` (the tile in particular) read it without prop-drilling through LiveKit's GridLayout. `localIdentity` is nullable because LiveKit's `localParticipant.identity` is briefly undefined on first render; consumers must check truthiness before comparing to prevent a one-frame race where a Co-host could self-mute via the server path. `hasEndAllAuthority` is consumed only by `RIMControlBar` and `EndMenu` (not by tiles), so it's passed as a direct prop rather than through the session role context.

**Krisp Enhanced Noise Cancellation + Bell mode (session 122, instrumented session 124):** Krisp NC is enabled by default on every join via `useKrispNoiseFilter()` from `@livekit/components-react/krisp`. The hook lazy-loads the Krisp WASM on first enable, applies the processor to the localParticipant's mic track, and exposes `setNoiseFilterEnabled` / `isNoiseFilterEnabled` / `isNoiseFilterPending` / `processor`. In `RIMConference`, a ref-guarded effect calls `setNoiseFilterEnabled(true)` once on mount — the state is component-local so it resets to ON whenever the conference component remounts (every session join). `noiseFilterAvailable = krisp.processor !== undefined` is the "Krisp actually loaded successfully" signal, used to gate the Bell mode UI; on browsers where Krisp isn't supported, the toggle is hidden entirely so it doesn't appear to lie about NC state. The "Bell mode" button lives in `RIMControlBar` between Settings and End, visible only when `isCoHost && noiseFilterAvailable`. Tapping it flips NC off (amber tint via `--color-alert`, label changes to "Clean voice"); re-tap returns to NC on (default styling, label "Bell mode"). Latency is ~20 ms locally plus normal WebRTC publish time; from a user-presence standpoint, instantaneous. Cost: metered usage on LiveKit Cloud; first invoice will reveal the actual rate (estimated $10–30/mo at RIM scale).

**Krisp lifecycle instrumentation (session 124).** The hook's internal Promise swallows errors silently (missing WASM, unsupported browser, mic-track race). `RIMConference.tsx` now logs every state transition with the `[rim-krisp]` prefix: requesting initial enable, processor available, mic-publication detected, attach verification at 500ms after publish, retry-on-miss, enable/disable transitions. The initial enable is wrapped in try/catch so a missing-WASM rejection surfaces in the console instead of disappearing. An attach-verification effect subscribes to `RoomEvent.LocalTrackPublished`, waits 500ms, reads `track.getProcessor()` directly, and retries `setNoiseFilterEnabled(true)` once if the processor is loaded but not attached (gated on `!isNoiseFilterEnabled && !isNoiseFilterPending` to avoid spam on republish cycles). Logs are intentionally unconditional so they fire in production (Vercel) for verification via DevTools — to be removed once Krisp's runtime state is confirmed in real sessions.

**Bell mode caveat (session 124 audit finding).** The browser's native `noiseSuppression: true` constraint in `audioCaptureDefaults` runs *before* Krisp NC in the pipeline. For non-teacher audio profiles (speaker, listener), native NS is on — meaning bells/bowls/gongs are filtered by the browser at the capture layer regardless of Krisp/Bell mode state. Bell mode only meaningfully affects the audio of users on the `teacher` profile, which requires a `ProgramTeacher` row for that program. The session-124 ProgramTeacher backfill closed this gap for the operational programs Jesse and Maria teach.

**Time-gated tokens + per-session rooms (session 126).** Two coupled changes that complete one design intent: every session is a discrete event with its own LiveKit room and its own chat history.

The token routes (`/api/livekit/token` and `/api/livekit/guest-token`) refuse to issue tokens outside a session's open window. Window opens at `Program.startDatetime - 22 min` (matches the dashboard host early-open epoch from session 121) and closes at `Program.endDatetime + 30 min`, falling back to `startDatetime + 90 min` when `endDatetime` is null. The new helper `lib/sessionWindow.ts::getActiveSessionWindow(program)` returns a discriminated union: `{ active: true, sessionDate, opensAt, closesAt, startsAt, endsAt }` when a session is open, or `{ active: false, reason, nextSessionDate, nextStartsAt, nextOpensAt }` with a `reason` of `before-window` / `after-window` / `no-session-today` / `no-future-session`. ADMIN and GUIDING_TEACHER bypass; guests have no bypass. Outside the window the route returns `403 { error: "session-closed", message, nextSessionDate, nextOpensAt, nextStartsAt }` — the session page surfaces `message` directly as the calm plain-English copy: "This session isn't open yet — it begins at 7:00 PM" / "This session has ended" / "No session right now. The next one is Tuesday at 8:15 AM." Helper for that copy is `describeInactiveWindow(window)`.

Room names are now per-session. `roomNameForProgram(slug, sessionDate)` was already designed to produce `slug-YYYY-MM-DD` when given a date, and `SessionChatMessage.sessionDate` was already in the schema — only the call site (the session page) never passed the date, so `roomNameForProgram` returned the bare slug for every recurring program. Now the server computes today's `sessionDate` via `getActiveSessionWindow` and uses it for the room name. Today's room is `good-morning-sangha-2026-05-26`; tomorrow's is `good-morning-sangha-2026-05-27`. Chat (filtered only by `roomName`) scopes itself per session automatically without any query change.

The token response now includes `sessionDate`. The session page (`/session/[slug]/page.tsx`) stores it and threads it through to: `RIMChat` (chat history GET + POST), the `SessionRoleContext` (so `RIMParticipantTile`'s mute action can include it), the `RIMControlBar` → `EndMenu` chain (end-session), the `ParticipantsPanel` (mute-participant + mute-all), and the page-level step-in fetch.

Three layers cover "forgot to End-for-All": explicit End-for-All (`endRoom(roomName)` deletes the LiveKit room and disconnects everyone), LiveKit's empty-room idle cleanup (~5 min default), and the time gate at the door (token route refuses to issue new tokens after the close window). Tomorrow's room is a fresh name regardless. Yesterday's chat stays in the DB as orphan rows that nobody queries.

Defense-in-depth assertion `lib/sessionWindow.ts::assertSessionDateInWindow(programSlug, sessionDate, roles)` is wired into mute-participant, mute-all, end-session, and step-in. Refuses if the caller-supplied `sessionDate` doesn't match the currently open window (ADMIN/GT bypass). Step-In is the highest-stakes route (it writes a `HostAssignment` row); the others have low blast radius (empty rooms; `endRoom` and `mutePublishedTrack` on a non-existent room are no-ops in LiveKit Cloud) but the assertion is applied consistently. Pre-commit reviewer sub-agent flagged this gap.

Format alignment with the schedule UI: the session window helper produces `sessionDate` via `scheduleUtils.shiftToDate(...).toISOString()` — the same path the schedule tool uses when writing `HostAssignment.sessionDate`. `resolveSessionRole`'s exact-match assignment lookup hits existing rows correctly. The DST drift in `shiftToDate` (24-hour increments, not wall-clock-preserving across DST boundaries) is a pre-existing platform-wide limitation; this helper inherits it deliberately rather than forking to a DST-correct shift that would mismatch existing data.

Policy: every program follows the per-session pattern. Confirmed mid-session — drop-ins like Good Morning Silent Meditation included. No exceptions for "continuous community spaces." Closes backlog `2026-05-24-002`.
